# 健人｜訓練日誌

個人化重訓及跑步日誌，採用純前端 HTML/CSS/JavaScript。正式網址（需先開啟 GitHub Pages）：https://easylearnfromtw.github.io/Builder/

## GitHub Pages

在儲存庫 **Settings → Pages → Build and deployment** 選 **Deploy from a branch**，選 `main` / `/(root)` 並儲存。部署完成後由上面網址開啟，請勿用 `/index.html` 以外的其他任意路徑。

## 第一次使用與本機資料

首次開啟且瀏覽器沒有儲存紀錄時，重訓次數、跑步里程、運動時間、體適能分數及圖表都從 **0** 開始，不會產生範例訓練。預設的運動菜單與每週目標只是操作模板，**不是既有訓練成績**。

若這個瀏覽器已存有真實紀錄，網站會自動讀取既有的 `kai-log-v1` 本機資料；舊版自動建立且標記 `ex: true` 的範例會移除，但不會刪除真實紀錄。跨裝置不會自動帶入資料，須由設定頁的備份匯入或 Strava 同步。

## 快速加入過去重訓與 iOS 操作

- **重訓 → 快速加入過去重訓**：顯示本機真實紀錄中最近 4 種不同的重訓（依名稱與動作順序去重）。新用戶沒有紀錄時保持空白，不產生假資料。
- **帶入編輯**：將當次動作、重量、次數、RPE、熱身組複製成今天的草稿，所有完成勾選維持未完成；完成訓練後才真正存成新紀錄。
- **快速記錄**：開啟日期與時間確認頁；只有點擊「確認加入紀錄」才會新增另一筆紀錄。請僅用於實際完成與上次相同內容的訓練。
- **訓練中 → 沿用上次組數**：單一動作也能一鍵帶入上次的重量、次數與組數；若本次已填寫過資料，需再按一次確認覆寫。
- **iOS Safari**：改善表單聚焦引發的自動放大、取消鍵盤出現時的強制置中平滑捲動；觸控裝置底部導覽不再隨滑動縮放。**未關閉使用者自行雙指縮放**。

## Strava 串聯

在網站右上角 **設定與備份 → 串聯 Strava → 第一次使用？展開 Strava 串聯教學** 有完整操作流程。

GitHub Pages 是公開靜態網站，無法安全保管 Strava Client Secret，因此須另外部署專案的 `strava-worker/` 至 Cloudflare Worker。請依 [Strava 後端部署說明](strava-worker/README.md) 設定 API App、Worker KV、機密環境變數。建立後，在健人設定頁填入 Worker 網址，再進行官方 OAuth 授權及活動同步。**在 Worker 尚未部署之前，不會自動完成 Strava 串聯。**

訓練資料存在目前瀏覽器的 localStorage；請定期在設定中備份。

## 訓練新版（2026-10-16）

- 重訓主入口改為胸、背、肩、手臂、腹／核心、腿；可勾選動作再開始訓練。原有菜單保留在「我的既有菜單」，既有紀錄與進行中的訓練沿用 `kai-log-v1`，沒有清空或改寫資料格式。
- 跑步拆成總覽 `#run`、記錄 `#run/new`、活動紀錄 `#run/history`、跑量趨勢 `#run/trends`。支援瀏覽器返回、前進與直接開啟子頁。未完成跑步表單另存在本機 `kai-ui-run-draft`，重新整理可繼續。
- 體適能改為**投入積分**，從所有已完成紀錄累加，不限 100 分，也不因超過 7 天而扣回；不是醫療體適能量表或疾病風險推估。詳情位於 `#score`，顯示分項、近 7 天新增、部位組數、逐筆活動分與公式。

| 分項 | 公式 |
| --- | --- |
| 重訓 | 有效組數 × 2 ＋ 分鐘 ÷ 5 ＋ 完成活動 5 分；至少一個有效組 |
| 跑步 | 公里 × 5 ＋ 分鐘 ÷ 10 ＋ 完成活動 5 分 |
| 健走 | 公里 × 3 ＋ 分鐘 ÷ 15 ＋ 完成活動 3 分 |
| 持續訓練 | 每個有完成活動的不同日期 2 分 |

每個分項取至小數一位後相加。同一類型紀錄的相同 ID 只計一次，範例、草稿與未來日期不計。修改、刪除後由紀錄重算。舊版已存組數視為已完成；新訓練只有勾選的組數會儲存。

## 3D 人體模型（2026-10-16）

重訓頁改為一個可互動的 3D 肌肉人體（自寫 WebGL2，不需額外套件）：

- **點身體部位**（胸、背、肩、手臂、核心、腿）：模型以彈簧動畫轉 45° 並放大到該部位，網址變成 `#lift/<部位>`。背部會從背面轉 45°；手臂、肩膀只框選面向鏡頭的那一側。
- **點細部肌群**：放大後每塊細部肌群有標籤與引線（共 21 塊，例如上胸／中胸／下胸、前／側／後三角、背闊肌、腿後肌）。點模型上的肌肉或標籤，下方列出「主要訓練」與「也會練到」的動作，網址為 `#lift/<部位>/<肌群>`；瀏覽器返回會回到全身。
- **跨部位排菜單**：勾選的動作保留在底部「已選動作」列（可跨部位，重新整理仍保留），按「開始訓練」才建立訓練。
- **本週練過標示**：右上火焰鈕開啟時，近 7 天練過的肌肉維持鮮紅、尚未練的轉淡；次要肌群以半組計算。
- 左右拖曳旋轉；「正面／背面」快速切換；桌機滑過肌肉顯示名稱與本週組數。
- **動作示範**：重訓頁的每個動作與訓練中的每張動作卡都有「示範」，3D 人體會實際做出這個動作（深蹲、硬舉、臥推、伏地挺身、划船、引體、肩推、側平舉、彎舉、捲腹、棒式等約 45 種軌跡，自訂動作依部位套用），主要出力的肌肉隨每一下發紅、協同肌群淡紅；可拖曳旋轉、點一下暫停，未在訓練中時可直接「加入今天的訓練」。示範會畫出示意器材：平板凳／上斜凳（依身體量好高度，腳踩地、背靠墊）、瑜伽墊、引體向上架、雙槓、坐墊，以及手上的啞鈴、槓鈴或 EZ 槓（跟著雙手移動）；地上的接觸陰影跟著動作走，躺著或懸吊時不會浮在半空。
- 人體穿著寬鬆、厚實的霧灰半透明帽 T 與深色短褲。帽 T 從胸口與肩胛垂下、在下襬羅紋前自然蓬起，有長袖與羅紋袖口、袖口上方堆疊的皺褶、手肘內側褶痕、平放在背上的帽子（頸邊一圈厚帽緣、背上自然垂墜）、兩條抽繩、袋鼠口袋；衣料是真正的霧面材質：先把衣服後面的身體畫到離屏畫面、模糊後再透過衣服呈現，肌肉輪廓柔和地透出來。短褲有鬆緊腰頭、前方抽繩、側縫與內縫、側開衩褲口。放大某個部位時衣服會自動變淡。
- 握持：手指以 MakeHuman 原始手指骨骼（CC0）預先算好「握拳」形態，示範時雙手真正握住啞鈴、槓鈴、EZ 槓、單槓與雙槓；把手穿過拳心，握槓時前臂與手腕會自動旋轉成正握（槓鈴彎舉為反握、雙槓為對握）。躺在瑜伽墊上的動作會讓身體、衣服與雙手確實貼在墊上。
- 防穿模：衣服在深度測試中略微靠前，彎曲的關節不會讓肌肉戳出布料；寬鬆衣服只畫最外一層；器材、地板以「衣服外緣」計算接觸；伏地挺身與棒式會依手（前臂）與腳尖自動算出身體角度，所有動作都以自動檢查確認槓鈴、啞鈴、凳子與地板不會穿過身體。
- 配色與網站一致：肌肉改為沉穩的玫瑰紅，肌腱為帶粉的珍珠色，頭部為暖象牙白；攝影棚式打光（左前上方主光、右側冷色補光、肌肉表面的緞面光澤），背景有柔和光暈與四角微暗。
- 風格為解剖圖（écorché）：精瘦、線條分明的體態（背闊肌收窄），紅色肌肉帶拉絲般的肌束與肌纖維紋理，白色肌腱與筋膜嵌在肌肉之間的溝裡；整顆頭是同一種瓷白（不做臉部肌肉、不上唇色），臉型依提供的照片取比例（V 型下顎、窄下巴、細直鼻樑），眉毛、睫毛線與虹膜只用雕刻的光影表現。頭髮為動漫／VTuber 風格的雕塑髮束：約 90 片獨立髮束分層疊壓、尖尾，中間偏左分線的瀏海與兩側鬢髮；每片髮束帶有擺動權重，拖曳或轉動模型時會依慣性微微飄動（開啟「減少動態效果」時不擺動）。

技術與相容性：

- 人體以 MakeHuman 的基礎網格（CC0）離線塑形：精瘦肌肉體型、東亞臉型比例，並用其骨架擺成自然站姿，壓縮後內嵌在頁面裡（約 370 KB）。開啟重訓頁時在 Web Worker 裡細分一次、貼上約 120 塊肌肉與 40 條肌腱、沿著皮膚解出每塊肌肉的纖維方向與肌肉之間的筋膜線，並在頭皮上長出髮束（桌機約 1–2 秒，手機稍久），不阻塞畫面；不支援 Worker 時改在主執行緒建立。
- 肌群邊界逐像素計算，標籤跟著模型移動；點選用 ID 緩衝區判斷，滑鼠／觸控都可。
- 瀏覽器不支援 WebGL2 時自動隱藏模型，部位卡片、細部肌群標籤與動作清單照常可用。
- 支援深色模式與「減少動態效果」設定；畫面靜止時停止繪製以省電。
- 新增 46 個內建動作並標註對應肌群與動作要點。**`kai-log-v1` 資料格式不變**：既有紀錄、菜單與自訂動作都保留，肌群對照表獨立存放在程式中，自訂動作會歸到其部位的所有肌群。

人體模型來源：[MakeHuman](http://www.makehumancommunity.org/) 1.x 系統資產（基礎網格、塑形 targets、預設骨架與權重），以 CC0 釋出；塑形與擺姿的離線腳本不隨網頁發佈。

測試另外新增 `tests/body-model.cjs`（部位→肌群→跨部位選取→開始訓練、無 WebGL 的後備流程、實際點擊 3D 模型轉 45° 與選取肌群；瀏覽器沒有 WebGL2 時第三項會自動略過）。

### 驗證

需要 Node.js、Playwright 和 Chromium。可先執行 `npm install --no-save --package-lock=false playwright`，再用 `node --test tests/*.cjs`（共 17 項，其中 5 項是 GPU 靜態檢查）。預設 Chromium 為 `/usr/bin/chromium`，其他安裝位置可用 `CHROMIUM_PATH` 指定。瀏覽器測試自行啟動暫時的本機 HTTP 服務；不使用真實帳號資料。若環境禁止本機 HTTP，可以先執行 `node --test tests/gpu-budget.cjs` 驗證 GPU 預算與 JS 語法。

## 3D GPU 效能調整（2026-10-17）

- 3D 人體的 WebGL 畫布採裝置感知像素預算，最長邊最高 2048 像素（2K）。一般觸控裝置最多約 330 萬像素、桌機約 430 萬像素；低記憶體／省流量模式則降至約 140 萬／210 萬像素。實際尺寸還受顯示比例、GPU 的 renderbuffer／texture 限制，以及 DPR 縮放限制；畫布 CSS 佈局和觸控座標均保持不變。
- Frosted 帽 T 的離屏多重取樣在觸控裝置或高解析度緩衝區最多 2×，其他情況最多 4×；高負載畫面減少模糊次數。放大查看肌群時衣物透明度歸零，避免遮擋標示。
- 觸控裝置的 3D WebGL 提交最多每秒 30 幀，2K 高負載桌面最多 45 幀，其他桌面目標 60 幀；鏡頭／動作骨架／標籤狀態照常更新，畫面靜止時停止持續渲染。
- 以上為**渲染成本上限**，非實機 FPS 或耗電測量數字；不同 GPU、Safari/Chrome 版本仍可能有差異。


## 肌肉標示準確性（2026-10-17）

- 3D 模型的細部標籤不再直接採用肌群的平均頂點位置，而是從 GPU 對目前可見人體表面產生的肌群 ID 圖層取出標記點。
- 標點只落在該訓練區域的實際可見像素內，避開邊界；左右側採獨立編碼，旋轉模型後重新計算。畫面中不可見的區域不會以錯誤的引線指向其他肌肉。
- 為控制手機 GPU 負載，標記掃描最高約每 175 毫秒進行一次，模型旋轉停止後會再掃描。桌面最高約每 120 毫秒一次；使用最長邊 384／512 像素的離屏辨識圖，不讀回整張 2K 畫面。
- 可執行 `node --test tests/muscle-labels.cjs` 驗證左右側、遮擋及不規則肌肉區域，另有 `tests/muscle-labels-browser.cjs` 可使用 Playwright 在 WebGL2 環境核對標記點與真實 GPU 點選結果。
- **解剖學範圍**：模型將部分細部解剖肌肉合併為運動訓練區域（例如「腹斜／前鋸肌」是合併訓練區，並非單一解剖肌肉），改善標點位置不等於已將所有肌肉分割成獨立的臨床解剖結構。此模型不應當作精密解剖圖譜。


## 3D 胸肌顯色與視覺驗收（v4.4，2026-10-17）

- **來源**：依 iPhone 實際截圖指出「上／中／下胸不易辨識、下胸紅色區域向腹部延伸」等問題，先校正原始肌群網格包絡線，再以 WebGL2 shader 的抗鋸齒輪廓與可見區域遮罩，限制胸部下緣異常延伸。
- **辨識**：胸大肌仍為一塊連續肌肉；畫面中的上、中、下胸是訓練強調區域（非三塊彼此獨立的解剖肌肉）。以淺紅、深紅和橘紅區分並用清晰引線定位。GPU picking 與標籤定位改用一致的肌群 ID 分區，避免手指點選和視覺標示不一致。
- **驗證**：`tests/muscle-labels-browser.cjs` 在 Chromium WebGL2 模擬六大部位的肌群標點、實際 framebuffer 顏色對比、胸肌下緣與各訓練區至少 10% 的可見面積；`tests/muscle-labels.cjs` 覆蓋不規則區域、左右側及遮擋。GitHub Actions 的 **Jianren Muscle Label Validation** 和 **Verify muscle labels** 已通過 v4.4 的最後驗證；Pages 部署成功。
- **操作**：使用 `https://easylearnfromtw.github.io/Builder/?v=4.4-20261017#lift/chest` 查看最新版。網站標題下方顯示「3D 胸肌分區清晰版 v4.4 · 10.17」即可確認載入正確版本。
- **限制**：自動化測試在 Chromium／SwiftShader 執行，並非 iPhone Safari 實機 FPS、耗電或所有旋轉角度的臨床解剖精確度認證。其餘肌群雖已進行可見性與點選測試，仍應配合使用者實際螢幕驗收。現有訓練紀錄、菜單與 `kai-log-v1` 資料格式未變更。
